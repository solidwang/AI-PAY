支付核心流程

三条关键链路：下单 → 支付 → 回调处理

▌ 链路 1：统一下单（POST /v1/charges）
商户服务端
pay-api
pay-channel
微信/支付宝
商户服务端 POST /v1/charges (API Key) pay-api
① 验证 API Key → 解析 App → 验证渠道配置
pay-core createCharge() channel
② 生成 charge_id(ch_xxx)，写库 status=CREATED
pay-channel 统一下单 API 渠道
③ 调微信 /v3/pay/transactions 或支付宝 alipay.trade.wap.pay
渠道返回 prepay_id / trade_no channel
④ 组装 credential（JSAPI签名 / H5 url / 支付宝跳转链接）
pay-api charge 对象 + credential 商户端
⑤ 更新 status=PENDING，返回完整 charge 对象
▌ 链路 2：异步回调处理（POST /v1/notify/*）
微信/支付宝
NotifyController
NotifyService
Redis + DB
渠道通知 POST /notify/wechat/:appId Controller
① 验证渠道签名（微信V3 RSA / 支付宝 RSA2）
幂等校验（Redis SETNX）
key = "notify:{channel}:{transaction_no}"
SETNX 成功 → 继续处理  |  失败 → 直接返回成功（已处理）
同时写 notify_record 表，status=processing
NotifyService updateChargeStatus() DB
② 查 charge → 校验金额 → UPDATE status=PAID, paid=true, paid_at=now
幂等收尾：更新 notify_record.status=success，释放 Redis key
异常处理：任意步骤抛异常 → status=failed，返回 FAIL，渠道会重试（最多3次）
Controller 返回 SUCCESS 渠道
③ 微信返回 {code:"SUCCESS"} / 支付宝返回 "success"
▌ 链路 3：退款（POST /v1/charges/:id/refunds）
前置校验
① 验证 charge 存在且 paid=true
② 累计退款金额 + 本次退款 ≤ 原订单金额
③ 生成 refund_id（re_xxx），写库 status=PENDING
④ 幂等 key = "refund:{refund_id}"
渠道退款
⑤ 调用 channel.refund() → 微信退款 API / 支付宝退款 API
⑥ 渠道同步返回成功 → 更新 status=SUCCESS
⑦ 更新 charge.amount_refunded += refund.amount
⑧ 若 amount_refunded = charge.amount → charge.status=REFUNDED
注意事项
微信退款为异步，需监听退款回调
支付宝退款为同步，直接更新状态
失败时保留 failure_code + msg
渠道抽象接口：PayChannel 接口定义 createOrder()、parseNotify()、refund()、query() 四个方法，微信和支付宝各自实现，核心业务代码零渠道感知。
